# Front end: file notes (moved from README.md)

### 1. Frontend (Cloudflare Pages)
The client-side is a static Single-Page Application (SPA) using Vanilla JavaScript, TailwindCSS (built into `tailwind.css`, see "Tailwind build"), and FontAwesome. JavaScript is strictly modularized into native ES Modules residing inside a `js/` directory.

* **`index.html` & `styles.css`:** Main entry point, the static layout shell (viewport uses `viewport-fit=cover` for iPhone safe areas), and custom styles: fade/scale/sheet animations, skeleton shimmer, attendance unsaved-changes indicator, pinned Class Summary columns, and the `dialog-open` scroll lock.
* **`js/globals.js`:** Core configurations (points to the Worker API domain via `CONFIG.API_URL` set to `https://2026-api.plv.workers.dev`), shared state (`AppState`), and a centralized API wrapper (`apiFetch`).
* **`js/components-utils.js`:** Contains shared UI utility functions, such as avatar URL formatting to bypass Google Drive hotlinking blocks.
* **`js/components-auth.js`:** Encapsulates authentication HTML component templates including the Login screen and Registration screen (including `Legally Blind` accessibility tagging).
* **`js/components-dashboard.js`:** Contains UI layouts for the fixed header, responsive profile sidebar (displaying the user's name and username), modals for Update Details, Change Password, Course Creation, Program Management, User Management (full screen on phones), and the Student Document Submission modal (bottom sheet on phones), plus the Submission History, Group Members and Details sheets.
* **`js/components-class.js`:** Manages Class Roster views (with `Legally Blind` accessibility badges and priority sorting), attendance controls (a single **Save All** button; a changed row also autosaves on its own), term settings, the Class Summary (full screen on all devices), Record Scores and Attendance Dates panels (full screen on phones), the Course Actions, Manage Student, Add Student and No Class Days sheets (bottom sheets on phones), performance summaries (with clickable Written, Narrative, Individual, Report, Tasks and Major Exam score cards), student management modals (with disability/eye condition tagging), and the Student Caller (Recitation Picker) modal interface.
* **`js/components-exam.js`:** Encapsulates the UI templates for the Exam Manager (full screen on phones; featuring a plain Create Exam button, the exam list, Bonus Question Manager, and Class Assignment & Schedule Configurator), the Lecturer Full-Screen Presentation Overlay, and the Student Full-Screen Accessible Exam Overlay with high-contrast controls.
* **`js/components.js`:** Acts as a barrel file to export shared utilities and UI components from the domain-specific component modules.
* **`js/router.js`:** Hash-based client-side router (`AppRouter`). Manages view toggling and triggers data loading routines asynchronously, including dynamic route parsing mapping to specific Class IDs.
* **`js/auth.js`:** Handles login (with password visibility toggling), registration (including dynamic program list loading), session management, DOM event delegation, dynamic form masking, user detail updates, password updating logic, interactive panel/modal toggling, global image viewing navigation, and user management status controls.
* **`js/course.js`:** Encapsulates the complete event binding lifecycle for Course Management, serving as the master orchestrator for actions, forms (including document upload processing and dynamic input toggling for files vs. URLs), student disability tag updates, inputs, and routing clicks across modular domain files.
* **`js/course-dashboard.js`:** Manages lecturer and student dashboard rendering views. For students, it automatically queries and renders the **Assigned Accessible Exams** section, complete with a voice read-aloud trigger and direct **Enter Exam** triggers.
* **`js/course-class.js`:** Handles detailed class screen rendering, student sorting algorithms (prioritizing seat numbers and `Legally Blind` accessibility tags), data population for roster elements, print-ready roster exports, and enrollment management overrides. The lecturer's `.view-summary-trigger` click is handled only by the delegated listener in `course.js`; do not bind it again here or the confirmation prompt fires twice.
* **`js/course-scores.js`:** Powers the lecturer's Record Scores modal (create, edit and delete assessments, enter per-student scores with Enter-key navigation) and renders each student's score cards and breakdown popups. Supported categories: Written (Quizzes/Long), Narrative, Individual, Performance (Tasks), Report and Major Exam.
* **`js/course-summary.js`:** Powers the lecturer's Class Summary modal: a searchable class-wide table per term (Mid, Final or both) covering attendance, participation and all assessment categories, with a CSV export. Student summaries are loaded concurrently.
* **`js/course-attendance.js`:** Controls core attendance metrics, term period calculation rules, no-class day mapping, draft caching storage, and batch persistence through **Save All** (`POST /api/attendance`, which replaces the whole day) and the per-row autosave (`POST /api/attendance/single`, which writes only that student's row). Never save one student through the bulk call: it would remove the other students.
* **`js/course-attendance-dates.js`:** Lecturer tool (Course Actions > Attendance Dates) listing every date that has attendance records, with change-date, delete and merge-two-dates actions. Merging adds participation points and keeps the stricter status per student (Absent > Late > Excused > Present).
* **`js/course-recitation.js`:** Manages the Student Caller spinning wheel logic. It features Mode 1 (weighted probability distribution favoring students with minimal scores) and Mode 2 (unique caller ensuring students are not called twice in a single day by caching lists locally).
* **`js/exam-builder-model.js` / `js/exam-builder.js`:** The Exam Builder (full-screen overlay on every device, opened from Manage Exams; questions are added with a purple + button that opens a question-type picker; Template, Import and Export buttons are in its header): a Google-Forms-style Form view and a spreadsheet Grid view editing the same questions (Multiple choice, Multiple answer, True or False, Identification, Numeric, Enumeration, Ordering, Matching, Essay, each with its own points; up to 10 choices or 10 matching pairs; Part numbers start at 1), saving through `/api/exams` and `/api/exams/update`. One column layout is shared by the grid, the CSV import and the CSV export: `Part | Type | Question | Choice A-J | Answer | Explanation | Bonus | Points` (enumeration and ordering list items in Answer separated by `|`; matching puts each pair in a Choice cell as `left | right`; numeric is `9.8 ± 0.1`; multiple answer is letters like `A, C`; `A / B` in an identification answer or enumeration item accepts either). The model file is pure data code (no DOM): row conversion, validation, CSV reading (`,` `;` or tab, old 6-column, Choice A-H and 0-based Part files still import) and writing. CSV or Excel (.xlsx, first sheet; the SheetJS reader loads from cdnjs only when an Excel file is picked) import (inside the builder) fills the questions so nothing is saved unchecked. When the builder is opened from a class it also shows a Record Scores panel (link and enable, term, category, dates, who can take it) that links the exam to the class on save, the same as Link & Assign Students.
* **`js/course-exam.js`:** Orchestrates the exam list (type chips, points, Edit, Export CSV, Copy), CSV import into the builder, the template download (via the builder), bonus question builder, class-level exam linking with date window scheduling and per-student access checkboxes, the lecturer exam presentation state machine, and the student dashboard **Accessible Exam Overlay** powered by the Web Speech API (`window.speechSynthesis`) with voice confirmation on choice selection, persistent local draft saving, and automatic score recording.
* **`js/omr-sheet.js`:** Layout of the printable bubble answer sheet (a 180 x 240 mm frame with four corner markers, a 6-digit student number grid `00-0000`, and up to 100 questions with 2-5 choices) and `buildSheetHtml()`, which produces the print-ready page for Letter or A4. The sheet shows an optional header (asked when printing, remembered on the device; the assessment name is not printed), one line for Name / Year & Section / Date, the instructions, then four answer columns. The compact student number grid sits at the top of the first column with question 1 right below it, so the page has little blank space. Its numbers are shared with `omr-scan.js`; change both together.
* **`js/omr-scan.js`:** Reads a phone photo or a live camera frame of that sheet using only native Canvas APIs (no libraries): adaptive threshold, corner-marker detection (the larger top-left marker fixes orientation), perspective mapping, then per-circle shading measurement. Returns the student number and one answer per question (`BLANK` = -1, `MULTIPLE` = -2), and draws a green/red/blue review overlay.
* **`js/omr-sheet.js`:** Printed answer sheet. When the exam has more than one part, a small `PART n` label is printed above the first question of each part (bubble positions are unchanged, so scanning is unaffected).
* **`js/exam-sets.js`:** Printed exam sets (A-F, default 4). Set A is the exam as written; other sets reorder questions inside each part and shuffle choices ("all of the above" style choices stay put). Seeded by the exam ID, so papers and keys always match. Builds the question-paper and answer-key print pages (Scan Answer Sheets > exam setup > Print question sets / Answer keys).
* **Exam sets on printed sheets (A-F):** the answer sheet prints a SET row (A-D...) when the exam has 2+ sets; the scanner reads it, grades each sheet with its own set's key, and lets the lecturer pick the set when it was not shaded (those sheets are not uploaded until a set is chosen). Saved scans keep the set (`Scan_Sheets.Set_No`) and all keys (`Scan_Sessions.Set_Keys`); both columns are added automatically. Records show per-question right/wrong/blank/double by Set A question number when there are several sets. `js/course-scan-review.js` and `js/course-scan-records.js` grade by set; `worker/worker.js` accepts `setKeys` and `sheets[].set`.
* **`js/exam-print.js`:** Manage Exams > each exam has **Print**: choose 1-6 sets, then print the questions or the answer keys. All question types are supported; sets reorder questions within each part and shuffle choices, ordering and matching items; each set's key is remapped. Scanned-sheet exams must use Scan Answer Sheets > Print question sets so the keys match the scanner.
* **Item analysis and corrections (Exam Results):** each question shows difficulty, discrimination (top vs bottom 27%, needs 8+ submissions) and flags (very hard, very easy, negative, weak). **Give everyone credit** or **Drop question** re-scores every submitted exam and the assessment scores at once (drop scales the rest to the same maximum); **Undo** reverses it. New endpoints `POST /api/exam-adjust`, `POST /api/exam-release`, `GET /api/student-exam-review`; new `Class_Exams` columns `Adjustments`, `Release` (added automatically).
* **Student review (`js/exam-review.js`):** the lecturer ticks "Let students review their answers" in Exam Results; students then see **Review my answers** on the completed exam card (their answer, the right answer, points, explanation; essay model answers stay hidden).
* **Faster Manage Exams (`js/course-exam.js`):** the exam list opens at once from the copy saved on the device, then refreshes from the server; if the server cannot be reached the saved copy stays ("saved copy (offline)"). The Exam Builder shows "Draft saved hh:mm" as it autosaves your unsaved work on the device.
* **Login rate limit (`worker/accounts.js`, `worker/shared.js`):** 5 wrong passwords for one account, or 30 from one address, lock further tries for 15 minutes (HTTP 429), on `/api/login` and the student exam login. Uses a new table `Login_Attempts`, created automatically. A correct login clears the account's count.
* **`tools/security-check.sh`:** run after deploying: `./security-check.sh https://<worker-url> https://<your-site>`. Checks the login gate (needs `SESSION_SECRET`), forged tokens, CORS (`ALLOWED_ORIGIN`) and the rate limit.
* **Printing (`js/print-preview.js`):** every print (exam papers, exam sets, answer sheets, class roster) opens an in-app preview with **Back** and **Print** buttons instead of a new browser window, so installed phone apps can always return. Exam papers print in two columns like a normal paper test (title, `Part 1: Multiple Choice`, lettered `a. b. c. d.` choices). You print ONE set at a time: choose the number of sets, then the set (e.g. Set C of 3). Same in Scan Answer Sheets > Print question sets / Answer keys.
* **Edit Class Details (class page > Edit details):** the old room-only edit is now a form for course code, title, day, time, room and target audience (course/year/section). Saved with `POST /api/update-course` (only the class's lecturer; enrolled students stay enrolled). Exam terms are still edited where they were.
* **Manage Exams cards:** the main actions stay visible (Link & Assign Students, Grade Essays, Results, Edit); **More** opens a collapsible row with Present, Bonus Qs, Print, CSV and Copy. Buttons keep their classes, so every action works as before.
* **Exam Builder cards:** each card has a small `+ <type>` button at the bottom-left that adds a blank question of the same type and part right after it. The Type column in spreadsheet mode is wider.
* **`js/components-scanner.js`:** Template for the Scan Answer Sheets dialog (full screen on phones, IDs `scannerModal`, `closeScannerBtn`, `closeScannerBg`).
* **`js/course-fab.js`:** Floating button on the class page (bottom-right, markup in `components-class.js`) is **Student Caller only** (`#openRecitationBtn`). Scan, Scores and Enroll Student are in the bottom tab bar and the More menu (Enroll Student: More > Enroll Student). The file also holds the bottom tab bar logic (below); the old speed-dial menu code stays but does nothing while `#fabMenu` is absent.
* **`js/course-scan-records.js`:** The **Saved Scans** tab of the scanner dialog (`#scnSavedView`). Lists saved scans per course; opening one shows class totals (average, highest, lowest, correct / wrong / blank / double-shaded), a per-question analysis (percent correct, count per choice, a warning when nobody got a question right) and a card per student. Each card can be opened to compare and fix answers with a live score preview; **Save correction** calls `POST /api/scan-sheets/correct`, which recalculates the score and updates that student's Record Scores entry. The original scan is always kept, so **Reset to scanned answers** works at any time, even months later.
* **`js/course-swipe.js`:** Phones/tablets (under 1024px): swipe a student row right = Present, left = Absent (90px or more; ignored when the touch starts on a button, the points area or an input, or is a vertical scroll). It presses the row's own status button and queues the same auto-save as a tap. Attendance buttons and +/- points buttons are 40px tall on phones, and a short vibration confirms a tap and a successful save.
* **Full-screen pages on phones:** Record Scores, Manage Exams and Scan Answer Sheets use `.app-page` (with `.sheet-panel`): slide-in from the right, a back arrow on the left of the header (the close button keeps its id; it shows a ✕ on tablets/desktop), safe-area padding, and a swipe from the left screen edge goes back (`course-swipe.js`, not while the live camera is open).
* **`js/course-pull.js`:** Pull down from the top of the class page or dashboard (under 1024px, no dialog open, not on lists that scroll) to reload it. On the class page it waits if attendance has unsaved changes. Toasts (`ui-feedback.js`) appear as bottom snackbars above the tab bar on phones (CSS in `styles.css`).
* **Installable app (`js/pwa.js`, `sw.js`):** because the site may only serve `.html`, `.css` and `.js`, the web app manifest and the icons (192/512 PNG, maskable) are generated in the browser (`pwa.js` adds `<link rel="manifest">` with a Blob URL, the apple-touch-icon and theme colour). `sw.js` (site root) caches the pages, scripts, styles and the Tailwind/Font Awesome CDN files network-first (4 second wait, then the last copy), so a deploy shows at once and the shell opens offline; the API is never cached. A bottom banner offers Install (Chrome/Android) or the Share > Add to Home Screen steps (iOS) to a logged-in user on phones; **Not now** hides it for good on that device.
* **Tabs over full-screen pages (phones):** Record Scores, Manage Exams, Scan Answer Sheets and the Course Actions menu ("More") are full-screen pages that end above the bottom tab bar (`#classTabBar` stays visible and usable; `a11y.js` `TAB_PAGES` keeps it out of the inert area). Tapping a tab closes the open page through its own close button and opens the next one (`CourseFab.openTab`); the active tab follows whichever page is showing, including when a page is closed by its back arrow or an edge swipe. Attendance Dates, No Class Days and Class Summary (opened from More) are full-screen pages too and count as More (`SUB_PAGES` in `course-fab.js`). The live camera and other dialogs still cover the bar. Class Summary's Student column is 118px on phones (avatar hidden), 220px from tablet width up.
* **Bottom tab bar (class page, phones only):** `#classTabBar` in `components-class.js`, styled in `styles.css`, handled by `js/course-fab.js`. Roster scrolls to top; Scores, Scan and Exams press the matching Course Actions button; More opens the menu. On phones it replaces the header Menu button (`.tabbar-hide`) and the speed-dial's Scan / Scores items (`.fab-dup`), and the speed-dial sits above it.
* **Course Actions menu (`components-class.js`, `styles.css`):** app-style bottom sheet on phones: tiles grouped as Students / Grades & Exams / Calendar (`.menu-tile`), Term Period Settings collapsed, slide-up animation on every `.sheet-panel`, swipe-down to close (a11y.js). Button ids are unchanged because handlers in course.js and the course-*.js modules find them by id.
* **`js/student-summary-ui.js`:** Student "My Course Summary" as an app page: gradient header with back arrow, seat/group/topic chips, Mid/Final term switch (tap or swipe; opens on Final Term once it has class days), attendance bar and percentage pill per term, shimmer skeleton while loading, and a fixed bottom bar with History and Upload Document. The Topic chip is full width (up to 2 lines); tap it to read the full text in a call-out. Score and attendance breakdowns (`#detailsModal`, used by the student and lecturer summaries and Record Scores) now open as a full-screen page with a back arrow. On the student summary the page opens below the summary header (course, seat/group/topic, term tabs; tapping a term closes it) and above the History / Upload bar, which lives outside `#studentSummaryModal` (`#ssActionBar`) so `a11y.js` keeps it usable. It only reads values the existing code writes into the page. Initialised by `router.js` after the dashboard renders.
* **`js/student-sheet-viewer.js`:** **View answer sheet** button in the score list (student summary, also when a lecturer opens a student's summary) for assessments that were scanned and have a stored photo. Opens that student's own photo full screen (tap to zoom) so they can check it is their paper. `GET /api/student-sheet-photo?sheetId&studentId` only returns the sheet of that student; `/api/student-summary` now returns `studentId` and, per assessment, `Sheet_ID` / `Sheet_Version` when a photo exists.
* **Photo sources (`PhotoCache.get`):** the copy still on the phone that scanned it (no download) -> the 7-day cache -> Google Drive through the Worker (kept afterwards) -> if the download fails, an older cached copy even past 7 days. The reviewer uses the same order, so a freshly scanned sheet can be reviewed and cropped before its upload finishes.
* **`js/unsaved-center.js`:** **Unsaved on this device** (tile with a count in the Admin page and in each class's Course Menu, and a button at the top of the profile panel): one full-screen list across all classes of attendance dates kept as drafts, scanned sheets waiting to upload, and exam answers not submitted. **Check** / **Check all** compare each date with the server and remove the copy when the server already has the same data; **Open class** jumps to the class (its banner offers Upload); **Discard** deletes a local copy after confirmation. Class names come from the dashboard's saved copies.
* **`js/course-pending.js`:** Server-verified draft cache for attendance. Every date with a device draft (`attendance_draft_<course>_<date>`) is compared with `/api/attendance`; identical data (or a No Class day) clears the draft ("confirmed saved"), anything else stays listed in the class banner **Not recorded on the server yet** with **Upload** / **Discard**, together with waiting scanned sheets. Runs on class open, when back online and when the app returns to the front. The Attendance Dates list marks such dates **Unsaved on this device**. Exam drafts (`acc_exam_draft_*`) are removed only after the server accepts the submission.
* **`js/course-scan-photos.js`:** Low-resolution photo of every captured answer sheet (longest side 1100 px, JPEG quality 0.5, about 100-200 KB). The small copy is made when the sheet is queued, kept in IndexedDB (`omr_photos_v1`), and sent to `POST /api/scan-sheets/photo` only after the sheet itself is confirmed saved; it is deleted from the phone only when the Worker confirms the Drive upload. Offline or failed uploads retry (on open, when back online). Photos of discarded sheets are purged after 10 minutes. A photo failure never blocks saving scores. Saved Scans shows **View photo** (full-screen viewer, tap to zoom, Open in Drive) so a sheet can be reviewed later or on another device.
* **`js/omr-crop.js`:** Straightens a captured sheet to its frame (the 4 corner markers) at 5 px per frame unit (`rect1` layout, 900x1200 JPEG, about 50-150 KB) and cuts out the row of any question using the printed-sheet geometry from `omr-sheet.js`. This straightened photo is what `course-scan-photos.js` uploads, so rows can be cut out on any device later.
* **`js/course-scan-review.js`:** Full-screen reviewer opened from Saved Scans. One student at a time with Previous / Next and a student picker (a dot marks unsaved corrections). Two columns per question: the cut-out photo of that question's row on the left, the choices (A-E) on the right; tap the chosen letter again to clear it. Colours show right / wrong against the key, notes show the scanned answer when it was changed. Save recalculates the score (also in Record Scores); Reset returns to the scanned answers. Only the photo of the student on screen is downloaded.
* **Photo cache (`PhotoCache` in `js/course-scan-photos.js`):** Downloaded review photos are kept in IndexedDB (`omr_photo_cache_v1`, keyed by Drive file id) and reused without downloading again; entries older than 7 days are removed every time the reviewer opens. Photos saved before the straightened layout existed are straightened on the device when first opened (`straightenLegacy` in `omr-crop.js` finds the corner markers again) and the straightened copy replaces the cached one, so they also get per-question crops. Only if the sheet cannot be found in the picture is the whole photo shown on top.
* **`js/course-scan-queue.js`:** Device cache (`localStorage` key `omr_pending_v1`) for scanned sheets not yet in the database (answers only, no photos). A sheet enters the cache when it is ready (student matched, not a duplicate on screen) and is deleted only after the server confirms the save, so an offline or closed page loses nothing. Uploads wait 3 seconds after the last edit (20 seconds while a live review is open), retry every 15 seconds (6 attempts, then **Upload now**), and run again when the browser comes back online or the scanner is opened.
* **`js/course-scanner.js`:** Lecturer tool (Course Actions > Scan Answer Sheets). The answer key comes from an exam in Manage Exams (multiple-choice questions only; identification questions are skipped) or is typed in (which also saves the exam in Manage Exams). Photos are read one by one, or with **Live Scan** (the in-dialog camera checks every frame for the four corner squares, shows a green outline and hints such as "Move closer" or "Too dark", and runs full screen and captures by itself once the sheet has been steady for 2 seconds; after one capture the camera closes and that sheet is shown right away in the same full-screen view (student, score, photo overlay, answers) with **Capture again** and **Back to scan menu** at the bottom; the sheet is also added to the review list). Each sheet is matched to a student by the shaded student number (digits only; the lecturer can correct the number, pick the student, or fix a misread answer), and duplicate students block saving. Saving finds or creates the assessment, **merges** with the scores already recorded (`POST /api/assessment-scores` replaces every score of an assessment), asks before replacing a different score, and caps `raw + bonus` at the assessment's Max Score, as the accessible exam does.
* **`js/ui-feedback.js`:** `UI` helper: non-blocking toasts (`UI.success/error/warning/info`) and a promise-based `UI.confirm` modal (`role="alertdialog"`). Use these instead of `alert()` / `confirm()`.
* **`js/skeletons.js`:** Static gray placeholder blocks shown while data loads (screen-reader friendly, contains no user data).
* **`js/date-utils.js`:** Local-timezone date helpers (`getLocalDateString`, `parseLocalDate`, weekday matching). Never use `toISOString()` for calendar dates: it returns the UTC date, which is the previous day in the Philippines before 8:00 AM.
* **`js/a11y.js`:** Dialog accessibility and phone behaviour, driven by the DOM so modals only need to toggle the `hidden` class. It makes everything behind the top dialog `inert`, sets dialog roles and labels, traps Tab, closes on Escape, and restores focus. On phones it also locks page scroll (`html.dialog-open`), lets the browser **Back** button close the top dialog (one history entry per closable dialog), and supports **swipe down** on a bottom sheet's handle or header to close it.
* **`js/app.js`:** The master orchestrator that imports and initializes all modules.
